# Dependencies and performance

**Default:** compare local implementation first without building both alternatives;
prefer a dependency when it owns the problem/obligations more clearly.
**Invariant:** proposals identify problem/local alternative, class/zone, role,
environments, transitives, license/provenance/security/maintenance, install/native
behavior, permissions, public-type effects, removal, approval and unknown facts.
Compare unweighted independently falsifiable before/after obligations across domain,
lifecycle/failures, environments, public surface/compatibility, security/supply chain,
operations and evidence. Each needs owner, violation condition and test/tool/external-
contract/review evidence. No biased splitting/bundling; totals show direction, not an
admission score. Provider obligations do not automatically become ours.

`System` is accepted environment used directly in its zone; `Integration` an adapter-
owned framework/platform/service boundary; `Implementation` a hidden owned mechanism.
Semantic core does not import Integration APIs. These are not three directories and
grant no third-party public-type exposure. The narrowest actual consumer declares its
real role; catalog/lockfile mechanics remain applicable Tooling/project obligations.

**Invariant:** approval precedes direct additions/transitive promotions, major upgrades,
runtime/peer/optional changes, install scripts/native code/permissions, material behavior,
reclassification and public third-party types. Prepare the comparison and reuse exact
approval. **Default:** compatible low-risk changes follow release-note review and
proportional checks; unused removal includes causal uses within scope, without separate
approval. No extra approval registry.

**Default:** one pass per semantic stage with linear-or-better time and auxiliary-memory posture. A
stage needs a result/invariant/reuse boundary; extracting a function does not make a
mechanical repeat semantic. **Invariant:** discuss non-single-pass choices beforehand
with input dimensions/bounds, passes, retained output, auxiliary memory and simpler
alternative; justified sorting/indexes are allowed. **Contextual choice:** full/partial
computation follows bounds, changed set, frequency, reuse, invalidation and working set.
**Default:** intermediate collections need a semantic boundary; no cosmetic copies.
**Invariant:** invalidation has an owner; partial recomputation is not inherently faster.
Numerical claims record platform/environment, data shape/volume, warm-up, repetitions,
statistic, evidence owner and threshold status. Only accepted thresholds support passed
budgets; otherwise measurements are diagnostic. Big-O is not latency. Use reproducible
owned evidence without mandatory benchmarks per edit or a prescribed runner.
