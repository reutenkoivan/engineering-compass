# Entries and delivery artifacts

**Invariant:** one authored public-entry map owns the supported surface; outputs,
exports and declarations agree. Private directories are not entries. **Default:** build
configuration owns the map and native tooling derives outputs/metadata; another accepted
native owner is valid with singular authorship. Shared mechanics do not own package
entries. Do not independently edit generated exports. For accepted built-package
contracts, consumers use supported specifiers; source aliases prove no boundary.
This is not a blanket alias ban.

**Invariant:** every derived artifact has authored source, generator, inputs and consumers.
Change source/regenerate; remove stale/unapproved outputs within owner scope. Generated
does not imply uncommitted, excluded from typecheck or unpackaged. Preserve agreed subpaths
during internal remapping. Use static import/entry enforcement and build evidence;
`.d.ts` presence proves not every type guarantee. Special declaration checks require an
especially strong concrete need, not mere type exposure.

**Invariant:** delivery contracts define consumer entries, runtime files, resources,
metadata and needed docs. Native packing realizes selection; checkout/build presence
proves no inclusion. Private intent cannot replace export/packing restrictions. **Default:**
native static artifact/package analyzers and inventories prove their properties; runtime
import/CLI/consumer execution proves its distinct guarantee. Each extra resource/check
targets our packaging/composition defect, not bundler internals. Verify promised formats,
conditions and environments only; ESM-only needs no CJS.

Development uses proportional checks, not perpetual packing. Delivery verifies the final
candidate after transformations and delivers **that candidate**; later changes need
corresponding evidence. Record candidate, scope, environment, results and gaps with
sufficient existing facilities. Required-file/type-link inspection differs from special
authored compile/declaration cases; those retain strong justification regardless of
script name. Artifact validity infers neither SemVer nor publication authority.

**Invariant:** consumer docs match the candidate and form a self-contained delivered
set selected by an explicit files allowlist/native equivalent. Local links remain inside
the set; package docs cannot depend on root research. Public external-contract references
may link their owners. Do not ship the entire internal history/agent instructions or replace required
reader docs with an unavailable skill during setup deduplication.

**Default:** minimal real examples need actual documentation purpose, a semantic owner
and sufficient existing-project evidence. Test the documented use, not a similar case;
align imports/inputs/outcomes after candidate changes. Static evidence proves its actual
property; runtime claims need execution. No quota, doctest parser, registry or special
declaration suite is implied. Tooling owns delivery/path usability, not all doc conventions.
